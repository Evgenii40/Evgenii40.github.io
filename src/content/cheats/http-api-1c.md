Если вы никогда не обращались к внешнему API из 1С — начните с первых трёх разделов: там объясняется, что вообще происходит и из каких частей состоит запрос. Дальше — по шагам, с кодом и проверкой на каждом этапе. Никакого опыта веб-разработки не требуется.

## Что такое «внешнее API» и зачем оно 1С

**[API](/glossary/#api)** — это программный интерфейс: набор «дверей», в которые одна программа может постучать, чтобы что-то узнать или сделать. Внешнее API есть у банков, маркетплейсов, сервисов доставки, Telegram, курсов валют — у любой системы, которая умеет общаться с другими.

1С умеет быть по обе стороны обмена:

- **исходящие запросы** — запрос уходит из 1С во внешнюю систему;
- **входящие запросы** — запрос приходит из внешней системы в 1С, и она его обрабатывает (см. [«Приём входящих через HTTP-сервис: свой REST с нуля»](/cheats/http-service-1c/)).

```
   1С  ──  HTTP-запрос (что и от кого нужно)  ──▶  Внешний сервис (API)
       ◀─  HTTP-ответ (данные или ошибка)     ──
```

Руками это выглядит так: зашли на сайт сервиса, скачали данные, занесли в 1С. Работает — пока данных мало. При потоке это рутина и ошибки. API позволяет 1С делать то же самое сама, по расписанию, без человека.

Типичные задачи: получить курсы валют и загрузить их в 1С, отправить СМС, забрать заказы с маркетплейса, выгрузить остатки на сайт, передать платёжку в банк.

## Что понадобится

- Сервер 1С (или регламентное задание) с **доступом в интернет** — запросы идут именно с сервера, а не с компьютера пользователя;
- адрес API и его **документация** — из неё берутся хост, путь (эндпоинт), метод и формат данных;
- **ключ или токен** — выданный сервисом «пропуск», если API не открытый;
- базовое понимание **JSON** — текстового формата, в котором данные ходят туда и обратно.

> **Важно.** Объект `HTTPСоединение` доступен только на сервере (и во внешнем соединении). В толстом клиенте его нет: запросы делают на сервере, а результат передают на клиент.

## Словарик новичка

Пять минут на эти слова сэкономят часы непонимания дальше.

| Слово | Что значит простыми словами |
|---|---|
| **API** | Набор «дверей», через которые одна программа общается с другой |
| **[HTTP / HTTPS](/glossary/#http)** | Правила, по которым идёт общение. HTTPS — то же, но зашифровано (TLS) |
| **Хост / сервер** | Адрес сервиса без протокола, например `api.example.com` |
| **[Эндпоинт](/glossary/#endpoint)** | Конкретный путь, «дверь», например `/v1/rates` |
| **[Метод](/glossary/#http-metod)** | Что мы хотим сделать: прочитать, создать, изменить, удалить |
| **Заголовок** | Служебная строка запроса: какое тело, какой токен, что хотим получить |
| **Тело запроса** | Основные данные, которые отправляем (обычно JSON) |
| **Код состояния** | Число в ответе: `200` — успех, `4xx` — наша ошибка, `5xx` — ошибка сервиса |
| **[JSON](/glossary/#json)** | Текстовый формат данных: `{"поле": "значение"}` |
| **[Токен](/glossary/#token)** | Пароль для программы. Сервис выдаёт его заранее, передаём в заголовке `Authorization` |
| **[Basic / Bearer](/glossary/#basic-auth)** | Способы авторизации. Basic — присылаем логин и пароль. Bearer — присылаем один токен («билет»): кто его предъявил, тот и допущен |
| **Таймаут** | Сколько секунд ждать ответ, прежде чем признать сервис недоступным |

## Как устроен один запрос

Запрос в 1С собирается из двух объектов:

1. **`HTTPЗапрос`** — что именно спрашиваем: адрес (путь), метод, заголовки, тело.
2. **`HTTPСоединение`** — куда идём: сервер, порт, при необходимости логин/пароль, прокси, таймаут.

Отправка — это вызов метода соединения, имя которого зависит от HTTP-метода. Соответствие такое:

| Что делаем | HTTP-метод | Метод 1С |
|---|---|---|
| Прочитать | `GET` | `Соединение.Получить(Запрос)` |
| Создать | `POST` | `Соединение.ОтправитьДляОбработки(Запрос)` |
| Заменить целиком | `PUT` | `Соединение.Записать(Запрос)` |
| Изменить частично | `PATCH` | `Соединение.Изменить(Запрос)` |
| Удалить | `DELETE` | `Соединение.Удалить(Запрос)` |
| Любой другой | — | `Соединение.ВызватьHTTPМетод(Метод, Запрос)` |

Возвращается **`HTTPОтвет`**: у него есть `КодСостояния`, `Заголовки` и тело (строка, двоичные данные или поток).

## Шаг 1. Простейший GET-запрос

Самый частый случай: получить данные и разобрать JSON. Для HTTPS пятым параметром передаём защищённое соединение.

```bsl
Функция ПолучитьКурсыВалют() Экспорт

    // Куда идём: сервер, порт, логин/пароль (пусто), прокси (пусто),
    // таймаут в секундах, защищённое соединение для https
    Соединение = Новый HTTPСоединение(
        "api.example.com",                   // сервер (без https://)
        443,                                 // порт: 443 для https, 80 для http
        , ,                                  // пользователь, пароль
        , 10,                                // таймаут, сек
        Новый ЗащищенноеСоединениеOpenSSL);  // для https

    // Что спрашиваем: путь и заголовки
    Запрос = Новый HTTPЗапрос("/v1/rates?currency=USD");
    Запрос.Заголовки.Вставить("Accept", "application/json");

    // Отправляем GET
    Ответ = Соединение.Получить(Запрос);

    // Проверяем код состояния, а не «выбросило исключение или нет»
    Если Ответ.КодСостояния <> 200 Тогда
        ВызватьИсключение "HTTP " + Ответ.КодСостояния
            + ": " + Ответ.ПолучитьТелоКакСтроку();
    КонецЕсли;

    // Разбираем тело ответа как JSON
    Чтение = Новый ЧтениеJSON;
    Чтение.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку());
    Данные = ПрочитатьJSON(Чтение, Ложь);
    Чтение.Закрыть();

    Возврат Данные;

КонецФункции
```

`ПрочитатьJSON(Чтение, Ложь)` — второй параметр `Ложь` означает «получить структуру данных как есть» (по умолчанию 1С перевела бы всё в соответствие).

## Шаг 2. POST-запрос с JSON и Bearer-токеном

POST отправляет данные наружу: создать заказ, отправить сообщение, загрузить остаток.

```bsl
Функция ОтправитьЗаказ(ЗаказJSON) Экспорт

    Соединение = Новый HTTPСоединение("api.example.com", 443, , , , 10,
        Новый ЗащищенноеСоединениеOpenSSL);

    Запрос = Новый HTTPЗапрос("/v1/orders");
    Запрос.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Запрос.Заголовки.Вставить("Authorization", "Bearer " + ТокенAPI());

    // Тело можно задать строкой или двоичными данными
    Запрос.УстановитьТелоИзСтроки(ЗаказJSON, КодировкаТекста.UTF8);

    Ответ = Соединение.ОтправитьДляОбработки(Запрос);

    Возврат Ответ.КодСостояния;

КонецФункции
```

Заголовок `Content-Type` сообщает сервису, в каком формате тело (`application/json`), а `charset=utf-8` — что текст в UTF-8.

Про `Authorization` и `Bearer` отдельно: `Bearer` (англ. «носитель») — это способ авторизации, при котором доступ даёт сам токен, как билет на входе. Кто предъявил действительный токен — тот и допущен, без логина и пароля. Поэтому токен равносилен паролю: его держат в тайне и передают только по HTTPS.

## Шаг 3. Собираем тело запроса (JSON)

Тело POST-запроса (Шаг 2) — это просто текст в формате JSON, например `{"amount":100,"currency":"RUB"}`. Получить эту строку можно двумя способами.

**Способ 1 — написать строку вручную.** Годится, когда JSON короткий:

```bsl
ТелоЗапроса = "{""amount"":100,""currency"":""RUB""}";
// помните: внутри строки 1С кавычка удваивается — "" это одна "
```

**Способ 2 — заполнить структуру и превратить её в JSON.** Надёжнее, когда полей много или они берутся из базы: 1С сама расставит кавычки, скобки и запятые, ошибиться в разметке JSON негде.

```bsl
// Обычная структура 1С: имя поля → значение
Заказ = Новый Структура;
Заказ.Вставить("amount", 100);
Заказ.Вставить("currency", "RUB");

// Превращаем структуру в строку JSON
Запись = Новый ЗаписьJSON;
Запись.УстановитьСтроку(Новый НастройкиСериализацииJSON);
ЗаписатьJSON(Запись, Заказ);
ТелоЗапроса = Запись.Закрыть();   // получилось {"amount":100,"currency":"RUB"}
```

Оба способа дают одну и ту же строку. Дальше она уходит в `Запрос.УстановитьТелоИзСтроки(ТелоЗапроса, КодировкаТекста.UTF8)` из Шага 2.

## Шаг 4. Авторизация Basic

Если сервис использует логин и пароль, 1С сама сформирует заголовок `Authorization: Basic ...` — достаточно передать их в конструктор соединения.

```bsl
Соединение = Новый HTTPСоединение("api.example.com", 443,
    "логин", "пароль", , 10, Новый ЗащищенноеСоединениеOpenSSL);
```

## Параметры соединения

Полный конструктор `HTTPСоединение` (после сервера все параметры необязательны):

| Параметр | Смысл |
|---|---|
| `Сервер` | Адрес без протокола: `api.example.com` |
| `Порт` | 443 для HTTPS, 80 для HTTP (по умолчанию подставляется сам) |
| `Пользователь`, `Пароль` | Для Basic-авторизации |
| `Прокси` | Объект `ИнтернетПрокси`, если выход в интернет через прокси |
| `Таймаут` | Секунды ожидания; `0` — ждать бесконечно (так делать не стоит) |
| `ЗащищенноеСоединение` | `Новый ЗащищенноеСоединениеOpenSSL` для HTTPS |
| `ИспользоватьАутентификациюОС` | Для доменной аутентификации (NTLM/Negotiate) |

## Типовые грабли

- **Таймаут обязателен.** Без него зависший внешний сервер подвесит сеанс 1С (или регламентное задание) надолго. Ставьте 10–30 секунд.
- **Кодировка тела.** `УстановитьТелоИзСтроки(Строка)` без указания кодировки может отправить не в UTF-8 — всегда передавайте `КодировкаТекста.UTF8` явно. И дублируйте это в `Content-Type` через `charset=utf-8`.
- **TLS-ошибки на Linux.** Серверу 1С под Linux нужен пакет корневых сертификатов (`ca-certificates`), иначе `ЗащищенноеСоединениеOpenSSL` не установит соединение. Свои CA-сертификаты подключаются через `СертификатыУдостоверяющихЦентровOpenSSL`.
- **Прокси.** В корпоративных сетях без прокси наружу не выйти — передайте `ИнтернетПрокси` пятым параметром конструктора.
- **Коды ответа.** `200` — успех; `4xx` — ваша ошибка (проверьте тело, там обычно JSON с описанием); `5xx` — ошибка сервера (стоит повторить запрос позже). Всегда проверяйте `КодСостояния`, не полагайтесь на отсутствие исключений.
- **Повторы (ретраи).** При `5xx` или коде `429` (слишком много запросов) не «долбите» сервис в цикле: выждите паузу и повторите ограниченное число раз. Лимиты запросов описаны в документации API.
- **Большие файлы.** Не читайте тело в строку: `Ответ.ПолучитьТелоКакДвоичныеДанные()` или поток (`Ответ.ПолучитьТелоКакПоток()`). При отправке — `УстановитьТелоИзДвоичныхДанных` и `УстановитьИмяФайлаТела`.
- **Безопасность токенов.** Токены храните в безопасном хранилище (`ЗащищенноеХранилищеДанных`), не в константах и не в коде. И не логируйте заголовок `Authorization`.
- **Один сервер — одно соединение.** Объект `HTTPСоединение` можно переиспользовать для нескольких запросов к тому же серверу — не создавайте его заново на каждый вызов.
- **Асинхронные методы на клиенте.** Начиная с 8.3.21 на клиенте обычные методы `Получить`, `ОтправитьДляОбработки` и т.д. устарели — там нужны `...Асинх` и `Ждать`. На сервере используйте обычные методы.
