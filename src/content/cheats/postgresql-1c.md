PostgreSQL — самая популярная бесплатная СУБД для 1С и «родная» для платформы в последних релизах: версия 8.3.27, например, отдельно оптимизирована под PostgreSQL в кластерном варианте. Шпаргалка — как поставить и не сломать на старте.

## Версии и что ставить

Для 1С подходят PostgreSQL 12–16 (актуальные типовые работают и с 15, и с 16; точный список — в документации конфигурации). Ставьте полный дистрибутив (установщик EnterpriseDB для Windows или пакет для Linux), но для 1С важны три вещи: разрядность x64, кодировка базы `UTF8` и корректная locale без сюрпризов, режим сервера (не single-user).

## Шаг 1. Настройка сервера под 1С

После установки правят `postgresql.conf` (в каталоге данных): `shared_buffers` — около 25% RAM (для 1С часто 4–16 ГБ), `work_mem` — сотни мегабайт на сложные запросы отчётов, `effective_cache_size` — 50–75% RAM, `max_connections` — с запасом от числа сеансов (каждый сеанс 1С держит соединение). В `pg_hba.conf` разрешают подключения сети приложений по `md5`/`scram-sha-256`. Если сервер 1С и СУБД на одной машине — оставляют `listen_addresses` с локальным адресом.

## Шаг 2. Создать пользователя и базу под 1С

Через `psql` от администратора:

```sql
CREATE ROLE srv_1c LOGIN PASSWORD 'strongpass';
CREATE DATABASE erp WITH OWNER = postgres ENCODING = 'UTF8'
    LC_COLLATE = 'C' LC_CTYPE = 'C' TEMPLATE = template0;
GRANT ALL ON DATABASE erp TO srv_1c;
```

В 1С при создании базы в консоли администрирования выбирают эту СУБД, указывают пользователя `srv_1c`; для загрузки конфигурации временно дают `CREATE EXTENSION`-права на `pg_trgm`, `hstore`, `pltcl` (нужны типовым) и право владения базой, после загрузки права понижают до рабочих.

## Шаг 3. Проверить

Консоль администрирования → база есть, сеанс открывается. Дальше — замер: `SELECT count(*) FROM pg_stat_activity;` растёт при открытии клиентов, фоновые vacuum-процессы не зависают на пустой базе. Обязательный минимум обслуживания: `ANALYZE` после массовых загрузок и планирование `VACUUM` (autovacuum обычно справляется сам, но после закрытия периода его стоит подтолкнуть вручную).

## Бэкап и восстановление

Логический бэкап — `pg_dump -Fc erp > erp_дата.dump`, восстановление — `pg_restore -d erp --clean dump` (обычно на пустую/пересозданную базу). Физический — базовые копии `pg_basebackup` + архивирование WAL: это для больших и быстрых выборок. В связке с 1С помните: дамп — только часть бэкапа, папки файлового сервера и отчёты бэкапятся рядом, см. [«Резервное копирование из командной строки»](/cheats/backup-cli-1c/).

## Типовые грабли

- **Смена версии платформы.** Новые версии платформы иногда требуют переустановки расширений/компонентов SQL — обновляйте PostgreSQL и 1С согласованно, на тестовой базе сначала.
- **Пул соединений.** Слишком низкий `max_connections` порождает ошибки «too many clients», слишком высокий — память под каждое соединение. Ориентир: сеансов 1С × 2 + запас.
- **Долгие запросы без анализа.** После загрузки данных без `ANALYZE` планировщик выбирает последовательные чтения вместо индексов — отчёты «вдруг» идут минутами. Правило: массовая загрузка — затем `ANALYZE`.
- **Локаль и порядок строк.** `LC_COLLATE = 'C'` даёт «неправильный» алфавитный порядок без учёта региона — для 1С это штатная рекомендация, порядок сортировки задаёт платформа; не «исправляйте» locale на лету.
- **Обновление major-версии** (14 → 16) — это `pg_upgrade` или выгрузка/загрузка, не автообновление; планируйте окно и проверку.
