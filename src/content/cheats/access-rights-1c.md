Сразу после установки «из коробки» почти всё умеет только администратор. Чтобы пользователи могли работать, а лишнего не видели, в 1С настраивают **права доступа**: кто какие объекты видит и меняет. Разберём, как это устроено и как ограничить доступ к отдельным данным.

## Что такое права доступа и RLS

**Права доступа** — это разрешения на действия с объектами: читать справочник, добавлять документы, проводить, удалять. Их не выдают пользователю по одному — их собирают в **[роли](/glossary/#rol)**, а роли — в **[профили](/glossary/#profil)**.

**[RLS](/glossary/#rls)** (от англ. Row-Level Security) — это ограничение доступа не ко всему объекту, а к отдельным **записям**. Простой пример: все менеджеры работают в одном справочнике «Клиенты», но каждый видит только своих.

```
Пользователь  -->  Профиль  -->  Роли  -->  Права на объекты + RLS
```

## Когда это нужно

Тема актуальна, когда добавили новый справочник или документ — сразу продумайте права, иначе пользователи его не увидят. Или когда в компании разные роли — менеджер, кладовщик, бухгалтер — у каждого свой набор прав. Или когда нужно ограничить видимость: «свой склад», «свои документы», «свой филиал».

## Словарик новичка

| Слово | Что значит |
| --- | --- |
| Право доступа | Разрешение на действие с объектом: Чтение, Добавление, Изменение, Удаление, Проведение. |
| Роль | Набор прав под одну простую задачу, например «Изменение заказов». |
| Профиль | Набор ролей, который назначают пользователю. |
| Пользователь | Учётная запись [информационной базы](/glossary/#informacionnaya-baza) (ИБ) для входа в программу. |
| RLS | Ограничение доступа к отдельным записям данных, а не ко всему объекту. |
| Параметр сеанса | Значение, доступное во время сеанса (например, текущий пользователь) — в том числе внутри запросов. |
| Привилегированный режим | Выполнение кода без проверки прав. |

## Что понадобится

- [Конфигуратор](/glossary/#konfigurator) (режим для настройки базы) и права администратора.
- Понимание, какие роли нужны именно вам (обычно подсказывает бизнес: «кто что делает»).

## Шаг 1. Роли и профили: как устроено

Схема простая: **пользователю назначают профиль, в профиле лежат роли, в ролях — права**.

Так одну и ту же роль можно выдать многим людям, а сотруднику — собрать набор ролей под его работу.

> **Правило.** Одна роль = одна элементарная функция: «Чтение номенклатуры», «Изменение заказов». Не делайте «толстых» ролей «на всё сразу» — их неудобно выдавать и проверять.

## Шаг 2. Права на объект: две роли

Для большинства объектов по стандарту делают **две** роли:

- `...Чтение` — только просмотр.
- `...ДобавлениеИзменение` — просмотр, добавление и изменение (изменение включает в себя чтение).

Пример имён: `ЧтениеНоменклатуры` и `ДобавлениеИзменениеНоменклатуры`.

> **Важно.** Не выдавайте обычным пользователям **интерактивное удаление**. Удаление помеченных объектов делают отдельной ролью — так данные можно случайно не стереть.

## Шаг 3. Ограничение доступа к записям (RLS)

RLS — это условие в правах роли, которое платформа подставляет в запросы. Классика: «пользователь видит только свои документы».

Порядок такой:

1. Завести **[параметр сеанса](/glossary/#parametr-seansa)** (например, `ТекущийПользователь`).
2. Устанавливать его в модуле сеанса, в обработчике `УстановкаПараметровСеанса`.
3. Использовать этот параметр в ограничении доступа роли.

```bsl
// Модуль сеанса. Параметр устанавливается «по требованию»,
// когда платформа его запросит (а не при старте).
Процедура УстановкаПараметровСеанса(ТребуемыеПараметры)
    Если ТребуемыеПараметры.Найти("ТекущийПользователь") <> Неопределено Тогда
        УстановитьЗначениеПараметраСеанса("ТекущийПользователь", Пользователи.ТекущийПользователь());
    КонецЕсли;
КонецПроцедуры
```

Теперь в **ограничении доступа** роли (в Конфигураторе, на вкладке «Ограничения доступа к данным») пишем условие:

```sql
ГДЕ Документ.Автор = &ТекущийПользователь
```

Так менеджер увидит только свои документы. Отдельное право на объект для этого не требуется.

> **Важно.** Параметры сеанса устанавливайте «по требованию», а не при старте сеанса: иначе это бьёт по скорости, особенно при RLS.

## Шаг 4. Проверка прав в коде

Если что-то нужно спрятать или показать в интерфейсе — проверяйте право на объект, а не название роли:

```bsl
Если ПравоДоступа("Редактирование", Метаданные.Справочники.Номенклатура) Тогда
    // показать кнопку изменения
КонецЕсли;
```

> **Неверно.** `РольДоступна("ДобавлениеИзменениеНоменклатуры")` — так проверять нельзя: роль это «деталь сборки», её состав и имя могут измениться. `РольДоступна` годится только для ролей-маркеров, у которых нет прав на объекты.

## Шаг 5. Обязательные (стандартные) роли

В конфигурации по стандартам должны быть три роли:

- `ПолныеПрава` — неограниченный доступ к прикладным данным.
- `АдминистраторСистемы` — системное администрирование (назначается только вместе с `ПолныеПрава`).
- `ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок` — открытие внешних отчётов и обработок.

Их указывают в свойстве конфигурации **«Основные роли»**. Интерактивное удаление — отдельная роль «Удаление помеченных объектов».

> **Важно.** `ПолныеПрава` намеренно **не** даёт интерактивное удаление — это защита от случайного стирания данных.

## Типовые грабли

> - **Все права в одной огромной роли.** Разбивайте по функциям, иначе нельзя выдать «половину» прав.
> - **Проверка через `РольДоступна`.** Используйте `ПравоДоступа` — роли можно переименовать или перегруппировать.
> - **Ролевая видимость элементов формы.** При большом числе ролей замедляет открытие форм — делайте отдельные формы или проверяйте права в коде.
> - **RLS без параметра сеанса.** Ограничение не сработает, если параметр не установлен.
> - **Фейковое право `ГДЕ ЛОЖЬ`** «для проверки роли» — так нельзя; проверяйте роль.
> - **Забыли про привилегированный режим.** Для проведения документов и получения функциональных опций есть отдельные требования.
> - **Дают интерактивное удаление пользователям.** Не давайте; удаление помеченных — отдельная роль.

## Куда развивать
